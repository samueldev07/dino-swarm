# Game UI craft — rules the user has already enforced

Every rule below exists because a shipped version was rejected as "xấu", "AI", "máy móc" or "không chuyên nghiệp".
Check the whole list before showing work. Verify on a phone-width viewport (375–412 px) and measure overlaps with
`getBoundingClientRect()` — screenshots of a hidden browser pane can be stale or mis-scaled.

## 1. Composition — avoid the "AI look"
- **Do not box every fact.** Chips, cards and bordered boxes around each value (type, par, reward, enemy, note) read as generic AI UI. Carry hierarchy with type size, weight, colour, spacing and thin rules. A panel gets at most one boxed element.
- **One shouting element per panel.** Primary action = filled button; secondary = quiet text/ghost button.
- **Never repeat a label.** If the battle title says "Tyr, God of War", the boss HUD does not; if the objective panel says "Rune Trial", the title plate does not.
- **No default browser UI**: no blue rounded boxes, system fonts, list bullets, `<details>` triangles, outline focus boxes in the art.
- **No "icon + bold title + grey description inside a bordered rounded card"** (e.g. a flag icon + "Rune trial" + description box in a stage brief). The owner crossed it out as AI design. Write it as type: a small uppercase gold label ("THE TRIAL") over one italic-serif line, no box, no icon, and no extra divider if the next section already has one.
- **Never show a meaningless or degenerate goal** ("Finish with HP ≥ 0%", "Within ∞ turns"). If a parameter is 0 or unset, change the rule (e.g. a second speed tier) instead of printing it.
- Progress is shown in-world (igniting rune sockets, filling medallions), not as a bare "1 / 2".
- **No "callout" boxes** (dark box + coloured left border) for tips, warnings or defeat advice — the most recognisable AI-UI pattern. Write the message on the scene: an ornamental rule, a serif/italic headline, a small label, quiet body text.
- Skill/ability states: an uncharged skill stays legible (muted saturation, ~80% brightness), never a black dead disc. Show charge as a ring filling around the socket, not a stray line under the name.
- **CSS ring masks: use `radial-gradient(closest-side, transparent calc(100% - 2px), #000 calc(100% - 1.5px))`.** `circle` defaults to farthest-corner, so a "50% - 2px" stop lands at ~35% of the radius and a "thin" charge ring renders 5–6 px thick (owner: "thanh nạp thô"). Measure the band in a zoom.
- **Icon-only utility buttons need a micro label** ("SOUND", "HINT") under them unless the glyph is universal. A symbolic metaphor (Odin's eye for hint) reads as nothing to players ("chẳng ai hiểu mắt đó là gì"). Use the convention (lightbulb = hint), filled glyphs at ≤20 px, and link automatic behaviour to its button (the idle auto-hint flashes the Hint button).
- **Never draw sound/roar as concentric arcs** (2026-10-09, Dino Camp Defenders: a roaring dino head with orange arcs was read as "khủng long wifi"). Concentric arcs = WiFi/speaker to every player. Show a roar/shout as a jagged comic burst, spiky shockwave star or flying spit/debris. Also test every small icon at 32-48 px on its real card colour without its label ("what is this?"): a winged foot at 64 px blurred into a "clover".
- **System/utility buttons must not look like gameplay pieces** (owner: "nhìn như skill rồi"). Skills = round painted medallions with charge rings; utilities (sound, hint, menu) = small rounded-square bronze plates with an isolated object glyph (transparent PNG, no backdrop disc), no ring, quieter label. Different shape + different framing = different category.
- **Lists of entries (saga chapters, logs, quests) are not stacks of bordered cards.** Use a timeline: one thin gold line, small rune medallions on it, small-caps label ("CHAPTER 3") · display title · italic 2-line excerpt, hairlines between entries, section headings (realm) as centred spaced caps between short rules with no box.
- Footer/skill trays must be **mirror-balanced**: a utility on the left (sound) needs a counterweight on the right (hint/Odin's eye); equal grid columns for all four skills. Ultimate art must fill its socket like the others (no padding/contain/brightness boost, which reads as a broken, washed-out icon).
- Footer/skill trays: fill dead side space with a quiet utility socket (sound toggle) instead of stretching the skills; group equal skills, a thin rule, then the ultimate; every socket centred on one line and every badge inside the tray (measure badge.bottom ≤ tray.bottom).
- Cost pills, badges and counters sit ON the rim of the thing they describe, never centred over the icon and never colliding with the line below. Measure: element bottoms must stay above the next row's top.
- Objective/goal panels on the battlefield must fit above the hero bar at phone height (measure the last line vs. the next panel's top).

- **Zones must read as zones** (owner: "thêm hub đơn giản ngăn ra" after everything was unboxed): battlefield · hero band · board · skill tray. Give the hero band and tray one shared light frame (dark glass + 1 px gold hairline) at exactly the board's framed width (`--board-w` from JS), with ~8–12 px gaps. Unframed floating rows look unfinished; heavy frames look cheap — the middle path is one hairline band.
- **Never cap the board so small that it floats in a wide window** (owner: "gameplay nhỏ quá"). Board cells scale with the viewport (cap ~64 px), and the HUD sockets are capped instead (~50 px), so gameplay stays the dominant element.

## 2. Frames and ornament — balance the detail
- **Heavy painted frames only on anchors** (the board). Panels get a light frame; bars and strips get thin metal rules; small items get nothing. If every rectangle has the same thick frame it looks heavy and cheap.
- Mix shapes: square board ↔ round skill sockets ↔ round medallion map nodes.
- 9-slice frames must have plain stretchable edges; ornaments only in corners (mid-edge ornaments smear when stretched).
- Prefer generating painted assets (G-Labs) over CSS imitations for anything ornamental; keep CSS for layout, light and motion.

## 3. Board pieces and special runes
- **Gem sprites must be isolated with transparency.** Baked black squares behind round gems look like dirty shadows.
- **Audit every keyed sprite numerically before shipping**: count semi-transparent alpha pixels (0 = hard binary cut → jaggies) and the mean luminance of edge pixels (dark = leftover backdrop ring). The charged runes shipped with 0 soft pixels and a dark 1 px fringe; a glow filter made it obvious ("tách nền bị lỗi"). Fix with a morphological opening (erode ~4 / dilate ~3: removes the fringe and painted light streaks poking past the silhouette), then feather the alpha (~0.75 px blur), keeping the original canvas size.
- Painted light inside a sprite (charged bands) is the signal — never add an outer CSS halo around it; it spills past the cell and outlines every keying flaw.
- Chroma key: magenta eats pink/purple subjects → use a green key (`key: 'green'`) for gems.
- **Decorations must stay inside their cell.** Anything extending past the tile is clipped by the board edge and looks broken on edge columns.
- **Special pieces get their own painted art per colour and direction** (charged-horizontal / charged-vertical / blast / cross). Do not draw CSS chevrons, blurry light bars or scribbled bolts on top of a normal gem. Never rotate a gem image to make the vertical variant — its symbol rotates too.
- One light model: key light painted in the art (top-left), a soft contact shadow below, a faint colour bounce on the socket. No fake white gloss blobs, no square halos.

## 4. Typography
- Use a fixed token scale (display / h1 / h2 / body / small / label / micro) with pixel floors; no ad-hoc `calc(var(--u)*N)` sizes.
- Names & titles in the display serif (Cinzel); anything read in the UI sans (Be Vietnam Pro); story voice in the italic serif.
- **No orphan words** (a single word alone on the last line): `text-wrap: pretty` on paragraphs, `balance` on headings/short labels, and glue the last two words with ` ` as a fallback.
- Numbers on bars must fit the bar height (bar ≥ 12 px when it carries text). Use tabular numerals.
- Never let separators collapse ("Stage 4Elite Battle", "Champion460 HP", "22 turns ·Par 9♡67%").
- **Matching a painted logo: carry it with the treatment, not a novelty face** (2026-10-10, Godbreaker, owner asked for headings in the logo's carved stone/iron style). A side-by-side sheet of ~20 Google faces in the same treatment showed the angular look-alikes (Germania One, New Rocker, Pirata One, Grenze Gotisch, Tektur) read as pulp/sci-fi and lose legibility at 18–24 px; Cinzel 900 stayed premium and kept one family with the Cinzel buttons. Render that comparison sheet before you change a face (`work/brand/type-compare.png`).
- **Forged display recipe** (`css/type.css`, tokens `--forge-*`, class `.forged` + `.ember` / `.frost` / `.rift`): `background-clip:text` metal-stone gradient with a hard horizon at ~50 % (light top band = the highlight), a 1 px dark bevel edge from four 0-blur `drop-shadow`s (±1 px x/y), a 2 px drop, and an optional glow (rift = orange left + ice-blue right, like the logo; defeat = charred iron with a dim ember). Rules that bit: **never use `text-shadow` on clipped text** (it paints over the gradient face; an older higher-specificity `text-shadow` rule made "Defeat" a flat salmon block, so set `text-shadow:none` at the same specificity as every competing rule and measure computed `textShadow`); **keep `color` solid and set only `-webkit-text-fill-color: transparent`** so inline SVG icons in headings (Quest journal, Camp) keep `currentColor`; never self-reference a custom property (`--forge-fill: var(--forge-fill)` silently invalidates the rule); a word on a backplate (combo banner strip) gets the treatment on an inner span, not on the strip element.
- **Full forged treatment only at ≥ 18 px.** 13–17 px names (battle title, enemy name, map realm) get a `lite` version: soft gradient without the horizon + a 1 px edge. Raise small overlay banners to an 18 px floor instead of shrinking the effect. Eyebrows, body, numbers and button labels stay plain.

## 5. Proportion and scale
- **Never force art into a box of a different aspect ratio** (`object-fit: cover` on a wider socket squashed the hammer). Lock `aspect-ratio: 1` for square art.
- Bosses must feel huge and scale by threat tier (normal < elite < guardian < god). Changing boss framing is a big call — **present options and wait for the user's choice** before implementing.
- Equal-weight items (skills) sit on one baseline with equal spacing; the ultimate may be larger but aligned.

## 6. Effects and motion
- Lightning must be organic (recursive midpoint displacement, forks, leader + return stroke + re-strikes with new shapes). Fixed-noise zigzags and hash-reseeded jitter read as "máy móc".
- Weapons/ultimates use the painted sprite, not a low-poly mesh. Give anticipation → impact → aftermath (ground sigil, shock rings, debris, dissolve).
- Motion is subtle and sparse (one sheen every ~10 s, gentle breathing). Everything decorative stops under `prefers-reduced-motion`.
- Effects anchor to visible ground (not behind HUD panels); verify impact points after any layout change.
- **The top special (World rune / colour bomb) must read as the most powerful thing on the board** (owner: "quá đơn giản", then "chưa ngầu lắm" for small seekers + a faceted diamond core). Recipe built 2026-10-09: charge with board vignette + white-gold core + a hairline turning Futhark ring that inhales; hit-stop; comet streams (cubic bezier, one swirl direction, nearest first, ≤30 ms stagger, tapered ribbon, white core, tip tinted to the struck rune); each target pops in its own colour (glow + fine ring + shards); finale shockwave ring across the whole board + bloom + camera kick + gold sparkle rain. Scale stream alpha by ~sqrt(10/n) so 30+ streams don't saturate into a white blob; keep every contact inside the battle wait (0.74 × duration).
- **Area-clear runes (Blast, 3x3) must read as the area they clear** (2026-10-11, owner: "hiệu ứng nổ của các rune này xấu" about a pale-cyan crystal flipbook that bloomed into an X/flower and ignored the rune colour). Recipe (`js/rune-fx.js` blast section, `tools/preview-blast.js`): ~150 ms arm (CSS swell 1.1 + brightness on the tile, rune-colour rim glow, motes inhaled, faint feathered warmth over the area) → detonation with a 55 ms hit-stop + small camera kick → a ROUND core flash (no spikes) and a soft feathered radial pressure band (cached annulus sprite, never stroked) that fades out as it crosses the area edge, plus a faint wobbling trailing band as heat shimmer; feathered area light (heavily blurred rounded-square mask, no visible edge) fills behind the front. **Never outline the area** — the first version's crisp rounded-square ring + hairline telegraph was rejected as "đóng khung" (boxed): the 3×3 must be felt through light, ripple and debris, not drawn → each cleared tile shatters on a 25 ms/cell ripple (the DOM tile fades via a class, the canvas paints faceted shards in that tile's colour, and the later clear skips its second break burst) → 400 ms scorch + rising embers + soft smoke. Colour = `luminous(rune colour)` (full-brightness same hue, then toward white); plain lighten() turns saturated runes pastel. Keep all fragments inside ONE board-clipped item with closed-form ballistic paths (shared particles are not clipped), cap ~85 per blast and halve when two overlap. Ramp the wave in over ~25 ms so the frame frozen by hit-stop is only the round flash. Fragments must not all launch from the exact centre on the same frame: spawn them off-centre and staggered or they read as a radial star.
- **Multi-piece motion needs overlapping action, not unison** (2026-10-11, owner about the match-4/5 fusion: "bị cứng, thiếu overlap motion" — every gem eased in on the same curve at once). Apply the classic principles and check them on a frame sheet (~20–30 ms steps, before/after): (1) anticipation — each piece lifts ~1.08 and winds back 2–3 px for 60–80 ms; (2) staggered/overlapping timing — farthest first, 30–45 ms apart, so arrivals cascade one after another instead of landing together; (3) arcs — slight curves that alternate sides, never dead-straight lines; (4) slow-in/fast-out into the goal with stretch along velocity (≤1.25×, volume-preserving) and a little spin; (5) 2–3 fading ghost copies instead of beads/comets; (6) secondary action — the receiver reacts to EACH hit (damped squash + push along the hit direction, accumulating swell/brightness), then a tiny inhale before the release; (7) follow-through — the result overshoots elastically (1.22 → .92 → 1.04 → 1, ~240 ms) and neighbours get a 2–3 px push-away wobble. Hand-off between canvas and DOM must match scale (canvas ends at the swell the CSS starts from) and reuse one animation name across classes that swap mid-way so it never restarts. Keep the awaited time short (~360–420 ms) — overlap makes it feel faster, not slower. Recipe: Godbreaker `actor-fx.gather`, `css/fusion.css`, `tools/preview-fusion.js`.
- Special-rune idle light: one thin rim glow in the rune's own colour on `.gem` (like charged runes) + contact shadow; never a fixed amber underlight/halo — on a dark cracked rune it reads as "muddy glow".

## 7. Process
- **`url()` inside a CSS custom property set from JS must be absolute** (`new URL(path, document.baseURI).href`). The variable keeps the raw text and resolves it against the stylesheet that consumes it (`css/…` → 404). A failed mask layer silently drops the clip: the charged-rune band light ran the full tile width as a stiff horizontal bar, and blast/cross sheens were unmasked. Check `getComputedStyle(el,'::after').maskImage` resolves to the real file.
- Cache-bust every local CSS/JS (`?v=`) on each change and show a visible build tag; the user repeatedly reviewed stale cached builds.
- When moving an element from `position:absolute` to flow, reset `inset`/`top`/`bottom` — leftover offsets from older sheets silently shift it.
- **Adding a pseudo-element (sheen/glow) to a piece: never change the host's `position`.** An absolutely-sized art box (`position:absolute; inset:0`) already anchors `::after`; switching it to `relative` collapsed blast/cross runes to 0×0, and players saw "mất rune" for days. After any CSS touching board pieces, measure every special type's art rect (> 0) in the live board.
- After a layout change that touches the board, re-verify hit-testing for every cell.
- Answer in Vietnamese, show before/after evidence, and list what still is not perfect.

## 8. HUD from research (2026-10-09)
Distilled from HIG/Material/Xbox accessibility docs, thumb-zone research, juice talks and match-3/puzzle-RPG teardowns.
Longer notes, per-element patterns and sources: `references/hud-research.md`. These refine §1–§6; where they overlap, this section is the stricter version.

**Weight and layout**
- **Three frame weights only: heavy (board), hairline 1–1.5 px (bars, hero strip, sockets), none (intent, floating numbers, praise).** A HUD that feels "thick" is fixed by thinning chrome, not by shrinking content; frame area is what reads as heavy.
- **Budget the 9:16 height: the board takes ≥ 50 %, all HUD strips (top bar + hero bar + skill row) ≤ ~28 %, the rest is boss art.** Measure with `getBoundingClientRect()`; if strips exceed it, cut chrome and padding before cutting the boss.
- **Three bands by function: threat at top (boss, boss HP, intent), state in the middle (hero HP/shield, turns), actions at the bottom (skills).** Mixed bands force the eye to zig-zag; the bottom is the one-hand thumb zone.
- **No nested boxes: a value never sits in a box inside a panel inside a frame.** Each level of nesting adds a border that carries no information (refines §1 "do not box every fact").
- **Interactive and essential text inside `env(safe-area-inset-*)`; art and scrims may bleed to the edges.** Notches and the home indicator eat taps and clip numbers.

**Controls**
- **Every tappable element has a ≥ 44 × 44 pt hit area (48 dp Android) and ≥ 8 pt between hit areas; art may be smaller, padding makes up the rest.** Apple/Material floor; fat-finger misses feel like the game cheating.
- **Every custom button has a press state (scale ~0.94 + darken, ≤ 80 ms).** HIG: without one the control feels unresponsive.
- **Skill = round socket, icon ~70 % of the disc, charge ring hugging the rim (2–4 px), cost/charge as a small rim badge at ~4–5 o'clock; no permanent name label, name on long-press.** Boxed cards with captions are the heaviest possible way to draw four buttons (refines §1 skill/cost rules).
- **Readiness is shown, not written: ring closes → one bright flash → slow breathing glow + full saturation; never a "READY" label.** Peripheral vision catches a pulse; it does not read words mid-match.
- **Rare actions (pause, settings, speed) go small in a top corner with a full 44 pt hit area.** Thumb-zone rule: frequent = easy reach, infrequent = hard reach.
- **Skippable auto-sequences (end-of-level bonus, 2026-10-11 Godbreaker "Valhalla's Wrath"): the whole screen is the skip target, and the "Tap to skip" hint sits under the running tally in empty space — not over the skill tray.** First capture put it on the tray, where it collided with the skill sockets and read as a button label. Dim the resting tray (opacity ~.45) while input is off; the tally is label + big tabular number + painted coin on a soft scrim, no box.

**Bars, numbers, intent**
- **Boss HP bar slim (8–14 px; ≥ 12 px if it carries text), with phase ticks at threshold %, and two fills: instant front fill + a pale "lag" fill that holds ~0.3 s then drains ~0.4 s.** The lag shows how big the hit was without a number; ticks show when the fight changes.
- **Enemy intent floats next to the enemy as icon + number, no plate: one silhouette per category (attack / guard / buff / debuff / special), magnitude as the number, turns-until as pips or a rim digit.** Spatial UI keeps cause next to source (Slay the Spire pattern); a chip in a corner must be cross-referenced.
- **Hero bar = one HP bar with the portrait medallion overlapping its left end; shield is an overlay segment on that bar, statuses are tiny icons with stack counts on their rim.** One composite object instead of 3–4 separate boxes.
- **Changing numbers use tabular figures in the UI sans, never the display serif; verify the shipped webfont really has `tnum` (compare widths of "1111" and "8888").** Proportional digits make counters jitter; some hosted font subsets strip `tnum` (refines §4).
- **Contrast comes from soft scrims (gradient/vignette 0 → ~60 % black) and a 1 px dark outline/shadow on text, not opaque panels; text meets 4.5:1 (3:1 for large) against the lightest pixel behind it.** Xbox XAG 102 measures against the worst spot; scrims keep the art visible.
- **Never encode state or element by colour alone: pair hue with glyph/shape/brightness.** ~8 % of men are colour-deficient and the art is already saturated.

**Icons, type, motion**
- **One icon family per strip: same material, same key light (top-left), same outline weight, same framing; pass the silhouette test (solid black at 24 px, each icon still distinct).** Mixed flat + painted icons is the fastest way to look cheap.
- **Size floors at 390 px width: body ≥ 14 px, labels ≥ 12 px, micro ≥ 11 px and only for non-essential info.** Apple's floor is 11 pt; anything smaller is decoration.
- **Feedback scales with importance and travels from cause to effect: tick for a match, orbs flying from cleared gems into the socket they charge, praise word for a big combo, shake/flash only for ultimates.** Royal Match teaches resource flow with motion instead of text; uniform max juice is noise.
- **Praise/combo text: centred over the board, display serif with outline, no backplate, ≤ ~900 ms, never over intent or HP; turn counter is one medallion that only gets loud (colour + pulse) at ≤ 3 turns.** Adaptive HUD: quiet when fine, loud when critical.
- **Before designing a HUD element, pull 3–5 references from gameuidatabase.com (filter: HUD element + mobile + genre) and name what you take from each.** Stops inventing generic UI from memory.

## 9. 3D runner scenes (2026-10-09, Dino Runner 3D)
- **A busy background is the first thing the user rejects ("nhìn hơi rối").** Value hierarchy: track clean and light, sides calm, only hero / obstacles / collectibles pop.
- Voxel textures: 8 px, 3–4 near-identical tones. 16 px high-contrast noise on every surface reads as clutter.
- Terrain beside the track: at most 2–3 height steps, not a staircase every block. Trees sit ≥ 6 blocks from the track, solid canopies (no random holes), few in number.
- No small loose props on the track (pebbles read as flying debris). Mark lanes with thin, low-contrast lines.
- With a curved-world vertex bend, subdivide long planes along z (one segment per unit), or a gap opens between the track and the blocks beside it.

## 9. Art-direction review lessons (2026-10-09)
Full review with specs: `<godbreaker>/work/art-direction/review-2026-10-09.md`.
- **Never hard-lock the game to a 9:16 box.** Phones are ~19.5:9; a `min(100vw, 100dvh*9/16)` box left 145 px of black bars (18 %) on 375×812 while the board was under budget. Fill `100dvh`, cap width, give extra height to the board, then the boss art.
- **Player HP and enemy HP never share a hue.** Both bars in the same crimson made it unclear whose life was dropping; hero = life green, enemy = crimson, plus different position/shape.
- **One object, one shape on every screen.** A skill that is a round socket in battle is not a square icon box in Camp; portraits/relics/skills/nodes are round, only the board and panels are rectangular.
- **Settings are rows with toggles/sliders, not a stack of identical buttons** ("Sound: On", "Music: On" as nine equal bordered buttons read as boxy and give no hierarchy). One gold primary (Resume), the rest quiet.
- **Destructive actions never share a style or row with navigation** ("Reset progress" looked exactly like "Field guide"): quiet danger-tone text link in settings, with confirmation.
- **Help/guide entries show the real in-game art**, never one generic glyph repeated (a sparkle for every special rune).
- **Token floors must equal the house floors.** `--fs-micro` 9.5 / `--fs-label` 10.5 let 8–9.5 px text spread to every screen; raise the tokens, then grep late sheets for literal px font sizes.
- **Test labels for clipping and modals for overflow at 375×667:** `scrollWidth > clientWidth` on buttons ("Eirik's sag"), and `scrollHeight > clientHeight` on panels (a visible scrollbar on the result card). Only a list may scroll; header and actions stay fixed.
- **Don't repeat the same fact across sections of one modal** (title = only enemy row, "1 wave" = "Wave 01", "Par 23" = "Within 23 turns"); hide sections that hold a single trivial value.

## 10. Text over a bright 3D scene (2026-10-09, Rex Run)
- **Thin white text with a soft shadow over a bright sky/sand scene was rejected as unreadable.** Overlay text gets a real outline (4-direction 2 px text-shadow, or `-webkit-text-stroke` + `paint-order: stroke fill` on display type) plus a dark scrim (~40–60 %) under modal screens.
- Sub-lines ≥ 17 px at phone width, weight 800. Never a keyboard legend on touch devices: detect `(pointer: coarse)` and write "Swipe…", otherwise "Press…".
- Teach mechanics in-world, one per obstacle, with near-frozen time (×0.04) until the right input, then a short "Nice!". No text walls on the start screen.
- Glowing collectibles: additive halo plane behind each coin + an occasional twinkle star, `toneMapped: false`, `depthWrite: false`. Emissive alone looks dull under ACES.
- **Flat-fill display titles with one outline colour were rejected ("thiết kế lại typo").** Use a logo-style title: vertical gradient face (light band top 34 %, saturated to deep bottom) via `background-clip: text` on a span, with outline + 2-step extrusion on a `::before` copy (`content: attr(data-text)`). Theme per screen (start gold + slight tilt, game over red-orange, pause icy blue). The primary action is a real chunky pill button, and stats are big numbers with small tracked labels, not one sentence.
- **Metal glints must be tinted by the base colour** (`diffuseColor.rgb * warm factor`) with only a tiny white core. A pure white band reads as "white stripe", not "shiny gold".

## 10. Owner feedback, 2026-10-09 (Godbreaker HUD rounds)
- **Status readouts are text, not chips.** Armour / Break / Vuln / Stun under a boss bar = one quiet row of icon + tabular number separated by hairline dividers on a soft scrim; never a bordered box per value. Hero armour = a small pill on the portrait rim. *Why: three boxed chips in a cluster read as "rất xấu".*
- **Sibling icons share one silhouette family.** XP next to Coin must be the same round medallion at the same scale; a tall shard beside a round coin looks off-centre. *Why: the owner flagged the mismatched XP icon as "lệch".*
- **Controls in one header are one family.** Help (?) and Close (×) = equal round glyph buttons, same rim, same baseline. *Why: a round ? next to a square × was called out.*
- **Skill icons for round sockets are designed for the circle:** bright centred subject (~68 %), lit backdrop in the skill's own colour darkening to the edge, no painted ring; check mean brightness at 46 px vs neighbours (target L ≈ 95–110/255). Uncharged state dims only slightly (brightness ≥ .9). *Why: dark square paintings cropped round made Thor's hammer vanish.*
- **Footer trays beat card rows:** one rounded tray holding round sockets with the count on the lower-right rim, names on long-press (Candy Crush booster tray pattern). Charge ring 1.5 px; a one-shot light sweep when a skill becomes ready.
- **Crowded headers: move actions, don't shrink them.** Frequent journey actions (Quests/Camp/Guide) go to the bottom tray; the header keeps back · title · currency · sound. Never ellipsize a title — reduce its size or drop the subtitle.
- **Class names can collide with art rules.** A status chip named `.board` inherited the game board's painted frame. Give HUD elements unique class names and grep the CSS for generic selectors (`.board`, `.panel`, `.frame`) before reusing a word.
- **Tutorial gesture cue = ONE thin white chevron (~5 px stroke, 48 px) with only a 1 px offset shadow, drifting gently along the swipe direction.** Rejected in order: hand in a gold badge ("thô"), three dark-outlined chevrons ("thô"), three chevrons with a faint wide halo ("viền to"). Less is the brief. Never CSS `drop-shadow` on stroked SVG. Keep arrow glyphs (←↑) out of text.

## 14. Speed (2026-10-12 whole-game pass, Godbreaker — measured at 4× CPU, phone viewport)
- **Never `#game:has(...)` / `body:has(...)`**: any DOM change re-checks it and restyles the whole game (was 2 700 invalidations/battle, 34 ms per style recalc). Toggle a class from JS on the nearest container instead.
- **No state class on a top container that pauses `#game *`** (hit-stop): it restyles ~1000 nodes per impact. Mark only the nodes from `document.getAnimations()`.
- Canvas FX must not call `getBoundingClientRect`/`getComputedStyle` every frame — cache layout, refresh on sync/resize or every ~500 ms.
- Restarting a CSS animation: just add the class if it is absent; batch the remove→re-add restarts into one style flush (microtask), never `void el.offsetWidth` inside a loop.
- Big sprite sheets (2k px): `img.decode()` at battle start, or the first drawImage decodes synchronously mid-combo (multi-second hitch on phones).
- Infinite decorative loops should animate only transform/opacity; background-position / box-shadow / color / text-shadow loops run on the main thread every frame.
- Asset diet: title video 1080×1920 at CRF 25 (7.8 MB → 2.6 MB, SSIM .98); PNG/JPG over 40 KB → WebP q88 (−5.5 MB). Keep PNG for flipbook sheets the tests pin.
- Measure with a CDP probe: tracing `UpdateLayoutTree` count/avg + `ScheduleStyleInvalidationTracking` changedClass, and sample `document.getAnimations()` for non-composited loops. Never measure while a test suite is running (CPU contention fakes hitches).
